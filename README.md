# Natural-to-SQL Assistant

A production-grade, local-first Natural Language to SQL analytics assistant built on MySQL 9.0, Ollama (`qwen2.5-coder:7b`), FastAPI, and Next.js 15.

---

## 11-Layer Defense-in-Depth Security Model

Every SQL query generated by the language model must pass through 11 security layers before data reaches the user:

1. **L1: Dedicated Read-Only DB User** — Granted `SELECT` only on the target database; denied all DDL, DML, and administrative privileges.
2. **L2: Read-Only Transaction** — Executed inside `START TRANSACTION READ ONLY` with explicit `ROLLBACK` in `finally`.
3. **L3: Server-Enforced Query Timeout** — `SET SESSION max_execution_time = 10000` prevents resource exhaustion and runaway joins.
4. **L4: AST Grammar Parsing** — Validated exclusively via `sqlglot` under MySQL dialect. Unparseable queries are rejected immediately.
5. **L5: Single-Statement Read-Only Whitelist** — Strictly allows `Select` expressions. Blocks multi-statements, stacked semicolons, and DML/DDL.
6. **L6: Table & Column Access Control** — Tables and columns are validated against the introspected schema and optional denylists.
7. **L7: Function Whitelist** — Blocks dangerous built-in functions (`SLEEP`, `BENCHMARK`, `LOAD_FILE`, `INTO OUTFILE`).
8. **L8: AST Token Normalization** — Re-renders SQL directly from the validated syntax tree. The raw LLM string is discarded.
9. **L9: Bounded Row Fetching** — Adds or enforces `LIMIT MAX_ROWS + 1`. Flags truncation in results.
10. **L10: Token Safety Token** — Engine requires a cryptographically guarded `SafeSQL` instance that can only be issued by the validator.
11. **L11: Result Sanitization** — Cells containing formula injection triggers (`=`, `+`, `-`, `@`, `\t`, `\r`) are sanitized before rendering or CSV export.

## Quickstart

### Prerequisites
- macOS or Linux with **Docker** installed.
- **Python 3.12** and [**uv**](https://github.com/astral-sh/uv).
- **Node.js 20+** and `npm`.
- [**Ollama**](https://ollama.com/) running locally with `qwen2.5-coder:7b`:
  ```bash
  ollama pull qwen2.5-coder:7b
  ```

### 1. Start Infrastructure
Start the deterministic seeded MySQL 9.0 container on port 3307:
```bash
make infra-up
```

### 2. Configure Environment
Copy `.env.example` to `.env` in the project root:
```bash
cp .env.example .env
```
Default configuration:
```env
TARGET_DB_URL=mysql+asyncmy://nl2sql_ro:nl2sql_ro_pass@127.0.0.1:3307/ecommerce
APP_DB_PATH=backend/data/app.db
OLLAMA_URL=http://127.0.0.1:11434
OLLAMA_MODEL=qwen2.5-coder:7b
MAX_ROWS=500
QUERY_TIMEOUT_MS=10000
```

### 3. Start Development Environment
Launch both the FastAPI backend (`:8000`) and Next.js frontend (`:3000`) concurrently:
```bash
make dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

## Troubleshooting

### MySQL Port Conflict
The dev container runs on port **3307** to avoid conflicts with standard local MySQL installations on 3306. Verify with:
```bash
docker ps --filter "name=natural_to_sql_mysql"
```

### Ollama Connection
If the health check returns `ollama: error`:
1. Verify Ollama is running: `curl http://127.0.0.1:11434/api/tags`
2. Check available models: `ollama list`
3. Ensure model is pulled: `ollama pull qwen2.5-coder:7b`

### MySQL 9.0 Authentication
MySQL 9.0 uses `caching_sha2_password` authentication. The `asyncmy` driver handles this over SSL or with server public key exchange configured in `app/core/db.py`.
